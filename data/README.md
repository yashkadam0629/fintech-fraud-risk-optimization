# Dataset

## What to download

**PaySim1 - Synthetic Financial Datasets For Fraud Detection**
https://www.kaggle.com/datasets/ealaxi/paysim1

Generated by the PaySim mobile-money simulator described in:
Lopez-Rojas, E. A., Elmir, A., & Axelsson, S. (2016). *PaySim: A financial
mobile money simulator for fraud detection.* 28th European Modeling and
Simulation Symposium (EMSS), Larnaca, Cyprus.

The simulator is calibrated on one month of real transaction logs from a
mobile-money provider operating in an African country. The Kaggle release is
scaled to roughly one quarter of the original volume.

## How to install it

1. Sign in to Kaggle and download the dataset (one CSV inside a zip, about
   180 MB zipped, 470 MB unzipped).
2. Unzip it.
3. Put the CSV in this folder: `data/raw/`

The filename does not need to match anything. `src/preprocessing.py` scans
`data/raw/` for any CSV whose header matches the PaySim schema and picks the
largest match, so a renamed download works fine.

Optional, using the Kaggle CLI:

```bash
pip install kaggle          # then place your kaggle.json API token
kaggle datasets download -d ealaxi/paysim1 -p data/raw --unzip
```

The raw file is **not committed to git** (see `.gitignore`). Anyone cloning
the repo re-downloads it with these instructions.

## Schema

Eleven columns, one row per transaction.

| Column | Type | Meaning |
| --- | --- | --- |
| `step` | integer | Hour index of the simulation, 1 to 744 (30 days). **Not a timestamp.** |
| `type` | text | `PAYMENT`, `TRANSFER`, `CASH_OUT`, `CASH_IN`, `DEBIT` |
| `amount` | float | Transaction value in the simulated local currency |
| `nameOrig` | text | Account initiating the transaction (`C` prefix = customer) |
| `oldbalanceOrg` | float | Initiating account balance before the transaction |
| `newbalanceOrig` | float | Initiating account balance after the transaction |
| `nameDest` | text | Receiving account (`C` = customer, `M` = merchant) |
| `oldbalanceDest` | float | Receiving account balance before the transaction |
| `newbalanceDest` | float | Receiving account balance after the transaction |
| `isFraud` | 0/1 | **Target variable.** Transaction was part of a fraudulent takeover |
| `isFlaggedFraud` | 0/1 | The simulator's own naive control rule, not a model output |

The spelling inconsistency is in the source file, not a typo here:
`oldbalanceOrg` has no `i`, `newbalanceOrig` does. `sql/01_schema.sql` renames
both to snake_case once, so PostgreSQL never needs quoted identifiers.

## Known limitations

Verify each against your own Stage 1 output rather than taking these on trust.

1. **No real timestamps.** `step` is a whole hour. Any feature finer than one
   hour (transactions in the last 10 minutes, seconds since last transaction)
   cannot be computed from this dataset and must not be fabricated.
2. **No geography.** No country, city, IP, device or merchant category.
   Geographic displacement and impossible-travel features are impossible here.
3. **Suspected target leakage in the balance columns.** The dataset
   description states that fraudulent transactions are cancelled, so the four
   balance fields are recorded after that reversal. `run_pipeline.py`
   quantifies this in the leakage audit and excludes them from the primary
   model.
4. **`isFlaggedFraud` is target-derived.** It is a control output, not an
   observation. Used as a benchmark baseline only.
5. **Thin originating-account history.** Originating accounts appear very few
   times each, which limits per-customer behavioural baselines. Measured in
   the account repetition section of the Stage 1 audit.
6. **Roughly 30 days total.** There is no 30-day rolling history for a
   transaction on day 3. The pipeline uses an expanding past-only baseline and
   publishes its coverage.
7. **Synthetic data.** Patterns come from a simulator. Model performance here
   does not transfer to a real payments portfolio.
8. **No monetary loss labels.** The dataset says whether a transaction was
   fraudulent, not what it cost to resolve. Every cost figure in this project
   is a stated assumption.
